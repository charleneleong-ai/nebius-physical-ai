Preflight · the training loop

Autopilot

The self-improving half of Preflight. Preflight decides whether the SO-101 robot should act; Autopilot learns from what fails. Each cycle reads the served GR00T N1.7 policy's benchmark, finds the generalisation axis (new objects, tasks or environments) with the most failures a tested recipe could fix, trains it, and lets a paired gate decide. Nemotron on Nebius Token Factory proposes; it never scores its own result.

Architecture: the agentic loop

An agent proposes; code decides. The only free choice the agent makes is which tested recipe runs next; everything that could flatter a result (the benchmark, the gate, promotion) is outside its reach.

How the gate decides: paired McNemar

Paired: the old and new policy run the same 96 scenes per suite (seed 42: same objects, same camera jitter), so they are compared scene by scene, not just as two totals.

new succeedsnew fails
old succeedsno informationnew lost it
old failsnew won itno information

Only scenes where they disagree count. If the new policy were no better, those would split like coin flips; the p-value says how unlikely the actual split is under that. A suite moves only at p < 0.05.

Cycle 1, read through the gate

suitewon / lostpreads as
basket (trained)+82 / −2<0.001real gain
ring (held out)+0 / −01.0no change: no transfer
clean_many+2 / −140.004real loss
real_1_pomade_tin+2 / −21<0.001real loss
held_out_objects+9 / −190.087leans worse, within noise

G3 asks two things: the target suites pooled are better (paired), and no suite anywhere is worse. A suite the recipe trains on directly doesn't count as a gain (basket), so cycle 1 had no target gain and two losses: DISCARD. With only 96 rehearsals, comparing totals (57 vs 61) can't tell luck from progress; pairing cancels each scene's difficulty, so small real differences show and luck doesn't count as a win.

The reference the latest cycle was planned against: 96 paired rehearsals per suite in the randomised twin. New tasks are the gap; seen scenes are the guard.

Requests from Preflight

Every scene Preflight would not clear is filed here as a learning request (npai autopilot intake). Recipes that answer one rank first. A refusal caused by an untrustworthy twin is a perception problem: it is recorded as unmet, not turned into training.

Cycles

{{CYCLES}}

The menu, ranked

Reach: failed rehearsals on a recipe's axes that fail the way it addresses. Nemotron chooses among the top three eligible; families every past attempt of which was discarded are closed.

{{MENU}}

Rules the loop can't break

  • One change per cycle, so every gain is attributable.
  • A fixed menu of tested scripts; the agent can't write or run anything else.
  • The gate is code (paired McNemar on the same scenes), not the agent. G3 counts gains on suites the recipe did not train on, and fails if any suite gets worse.
  • Closed families ({{CLOSED}}) are reopened only for refusals they were never tried on, rank after open recipes, and Nemotron is shown what closed them.
  • Promotion needs a human. GPU use waits for free memory, so other jobs on the host are never displaced.
